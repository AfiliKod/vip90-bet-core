# İP-9d Net Gaming Revenue (NGR) Definition, Deduction Engine, and Partner Billing Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement work package İP-9d of the approved multi-tenant architecture per Platform Owner decision K28 (2026-11-13):
- **K28 Partner Commission uses NGR:** Partner commission uses Net Gaming Revenue (NGR) while keeping the calculation base fully configurable (`ggr`, `ngr`, `turnover`, `fixed`) per partner and per `PartnerOperatorLink`.
- **Flexible NGR Definition (`NgrDefinition`):** Platform-level versioned model defining selected GGR components (`casino`, `sports`) and an ordered list of deduction items (`bonus`, `provider_fee`, `tax`, `chargeback`, `other`). Sources supported: `stat_field` (e.g. `bonusCost`, `chargebacks`), `fee_plan` (operator's active `OperatorFeePlan` component such as sportsbook fee), `rate` (percentage of GGR or turnover), and `fixed` (amount per day or period).
- **Strict No-Double-Deduction Protection:** Enforced at save time (HTTP 400 with explicit error codes) and re-verified at calculation time:
  1. At most one enabled item per category, unless category is `other` with distinct labels.
  2. A source key (`stat_field` name, `fee_plan` component, or rate target) may back only one item.
  3. Deductions cannot target GGR components already net of that cost (`ggrAlreadyNetOf` guard).
- **Definition Immutability:** Any version of an `NgrDefinition` referenced by an issued statement (`status === 'issued'` or `'settled'`) is strictly immutable; edits automatically create a new version.
- **Pure Calculator NGR Engine:** NGR for a day = selected GGR components − sum of enabled deductions calculated in integer minor units (cents) with rational arithmetic and single rounding per line. Negative NGR follows `negativeBaseHandling` (`zero_floor` or `deduct`, aliased to `negativeGgrHandling` for backwards compatibility).
- **TenantDailyStat Aggregation Enhancement:** Add required financial fields `chargebacks` and `providerFees`. `chargebacks` is populated from completed ledger `reversal` and `refund` transactions; `providerFees` defaults to 0 with documented provenance (external provider invoices not tracked in core ledger).
- **Removal of `ERR_NGR_NOT_IMPLEMENTED`:** Enable full NGR computation while preserving 100% backwards compatibility for existing GGR, turnover, and fixed calculations.
- **Platform Console & Partner Portal Visibility:** Platform Console allows configuring NGR definitions with real-time validation error feedback and attaching definitions to partner terms. Statement details in Platform Console and Partner Portal show itemized deduction breakdowns per line and totals.
- **Auditing & Single-Mode Isolation:** Every definition create, edit, version increment, and deletion is recorded via `writePlatformLevelAudit`. In single-tenant mode (`TENANCY_MODE=single`), all NGR routes return 404 `NOT_FOUND`.

**Architecture:**
- **Platform Model `NgrDefinition`:** Platform-level collection (never tenant-scoped). Carries `name`, `version`, `status`, `ggrComponents`, `ggrAlreadyNetOf`, `items`, and legal retention. Indexed uniquely on `{ name: 1, version: 1 }`.
- **Temporal & Versioned Terms Resolution:** Statements bind to an exact `(ngrDefinitionId, ngrDefinitionVersion)`. When terms are edited, existing issued statements retain exact historical figures.
- **Deterministic Minor-Units Arithmetic:** Deductions and NGR are calculated exclusively in integer cents. Rounding occurs half-away-from-zero once per line.
- **Zero-Drift Multi-Currency Partitioning:** Separate calculations and statement lines per currency.

**Tech Stack:** Node >= 22 (ESM), Express 4, Mongoose 8.24, React 19, Vite 5, Tailwind CSS, `node:test` + `node:assert/strict`, local MongoDB replica set (`rs0`).

## Reviewer Corrections and Ground Rules

1. **Deterministic Integer Minor Units:** Every monetary component (GGR, bonus, chargeback, provider fee, tax, fixed deduction) must be converted to integer minor units (cents) before arithmetic. NGR = GGR cents − sum(deduction cents). Division and percentages use rational math `divideRationalHalfAwayFromZero(num, den)`.
2. **Strict Double-Deduction Prevention (Save & Runtime):**
   - At most one enabled item per category (`bonus`, `provider_fee`, `tax`, `chargeback`). Multiple items allowed only for `other` with distinct labels.
   - At most one item per physical data source (`stat_field` name, `fee_plan` component, rate target).
   - If `ggrAlreadyNetOf` lists a category, no deduction of that category may be enabled (`ERR_NGR_ALREADY_NET_OF`).
   - If an unvalidated object bypasses Mongoose, `commissionCalculator.js` re-evaluates the same rules and throws `ERR_NGR_DOUBLE_DEDUCTION`.
3. **Immutability of In-Use Definition Versions:** If any statement with `status: { $in: ['issued', 'settled'] }` references `(ngrDefinitionId, version)`, that document version cannot be mutated. Mutations produce version `N + 1`.
4. **Data Integrity for Missing Ledger Sources:**
   - `chargebacks`: Aggregated from real `Transaction` records where `type: { $in: ['reversal', 'refund'] }` and `status === 'completed'`.
   - `providerFees`: Document explicitly that third-party game provider invoices are not stored in core transactions today. Defaults to 0; never invent mock records.
5. **Backwards Compatibility:**
   - Existing statements and commercial terms with `model: 'revshare_ggr'`, `turnover'`, or `fixed` continue to run unmodified.
   - `negativeGgrHandling` is aliased to `negativeBaseHandling`; both properties are accepted.
6. **Cross-Partner Isolation (K27):** Partner staff viewing statements can only see deduction breakdowns for their own partner scope (`req.staff.scopeId`). Requests for other partner statements return 404 `NOT_FOUND` (never 403).
7. **Test Isolation:** Tests must run on isolated database URIs (`mongodb://127.0.0.1:27017/vip90_test_ip9d_t*`) with `--test-timeout=60000`. Never run root `npm test`.

```javascript
import mongoose from 'mongoose';

const { ObjectId } = mongoose.Schema.Types;
const RETENTION_MS = 5 * 365 * 24 * 60 * 60 * 1000; // 5 years min per K24

const deductionItemSchema = new mongoose.Schema({
  category: {
    type: String,
    enum: ['bonus', 'provider_fee', 'tax', 'chargeback', 'other'],
    required: true,
  },
  label: { type: String, required: true, trim: true },
  enabled: { type: Boolean, default: true },
  source: {
    type: String,
    enum: ['stat_field', 'fee_plan', 'rate', 'fixed'],
    required: true,
  },
  params: {
    field: { type: String, default: null },
    component: { type: String, default: null },
    target: { type: String, enum: ['ggr', 'turnover', null], default: null },
    rate: { type: Number, default: null, min: 0, max: 1 },
    amount: { type: Number, default: null, min: 0 },
    period: { type: String, enum: ['day', 'period', null], default: 'day' },
  },
}, { _id: false });

const ngrDefinitionSchema = new mongoose.Schema({
  name: { type: String, required: true, trim: true },
  version: { type: Number, required: true, default: 1, min: 1 },
  description: { type: String, default: null },
  status: {
    type: String,
    enum: ['draft', 'active', 'archived'],
    default: 'active',
    index: true,
  },
  ggrComponents: {
    type: [{ type: String, enum: ['casino', 'sports'] }],
    default: () => ['casino', 'sports'],
    validate: {
      validator: (arr) => Array.isArray(arr) && arr.length > 0,
      message: 'At least one GGR component must be selected',
    },
  },
  ggrAlreadyNetOf: {
    type: [{ type: String, enum: ['bonus', 'provider_fee', 'tax', 'chargeback', 'other'] }],
    default: () => [],
  },
  items: {
    type: [deductionItemSchema],
    default: () => [],
  },
  createdBy: { type: ObjectId, ref: 'StaffAccount', required: true },
  updatedBy: { type: ObjectId, ref: 'StaffAccount', default: null },
  legalRetentionUntil: {
    type: Date,
    default: () => new Date(Date.now() + RETENTION_MS),
  },
}, { timestamps: true });

ngrDefinitionSchema.index({ name: 1, version: 1 }, { unique: true });

// Pre-save validation: No double deduction rules
ngrDefinitionSchema.pre('validate', function (next) {
  const enabledItems = (this.items || []).filter((item) => item.enabled);

  // 1. At most one item per category, unless category is 'other' with distinct labels
  const categoriesSeen = new Set();
  const otherLabelsSeen = new Set();

  for (const item of enabledItems) {
    if (item.category === 'other') {
      const normalizedLabel = (item.label || '').trim().toLowerCase();
      if (otherLabelsSeen.has(normalizedLabel)) {
        const err = new Error(`Duplicate label "${item.label}" in category "other" is not allowed.`);
        err.code = 'ERR_NGR_DUPLICATE_LABEL';
        return next(err);
      }
      otherLabelsSeen.add(normalizedLabel);
    } else {
      if (categoriesSeen.has(item.category)) {
        const err = new Error(`Category "${item.category}" cannot be deducted more than once.`);
        err.code = 'ERR_NGR_DUPLICATE_CATEGORY';
        return next(err);
      }
      categoriesSeen.add(item.category);
    }
  }

  // 2. Source key uniqueness
  const sourcesSeen = new Set();
  for (const item of enabledItems) {
    let sourceKey = null;
    if (item.source === 'stat_field' && item.params?.field) {
      sourceKey = `stat_field:${item.params.field}`;
    } else if (item.source === 'fee_plan' && item.params?.component) {
      sourceKey = `fee_plan:${item.params.component}`;
    } else if (item.source === 'rate' && item.params?.target) {
      sourceKey = `rate:${item.params.target}`;
    }

    if (sourceKey) {
      if (sourcesSeen.has(sourceKey)) {
        const err = new Error(`Source "${sourceKey}" is referenced by multiple deduction items.`);
        err.code = 'ERR_NGR_DUPLICATE_SOURCE';
        return next(err);
      }
      sourcesSeen.add(sourceKey);
    }
  }

  // 3. Deduction cannot target category already in ggrAlreadyNetOf
  const alreadyNetOf = new Set(this.ggrAlreadyNetOf || []);
  for (const item of enabledItems) {
    if (alreadyNetOf.has(item.category)) {
      const err = new Error(`Category "${item.category}" is already net in GGR and cannot be deducted again.`);
      err.code = 'ERR_NGR_ALREADY_NET_OF';
      return next(err);
    }
  }

  next();
});

export default mongoose.models.NgrDefinition || mongoose.model('NgrDefinition', ngrDefinitionSchema);
```

```javascript
export async function createNewVersion(req, res, next) {
  try {
    const original = await NgrDefinition.findById(req.params.id);

    const { description, ggrComponents, ggrAlreadyNetOf, items } = req.body;

    const latest = await NgrDefinition.findOne({ name: original.name }).sort({ version: -1 });
    const nextVersion = (latest?.version || 1) + 1;

    const newDef = await NgrDefinition.create({
      name: original.name,
      version: nextVersion,
      description: description !== undefined ? description : original.description,
      ggrComponents: ggrComponents || original.ggrComponents,
      ggrAlreadyNetOf: ggrAlreadyNetOf || original.ggrAlreadyNetOf,

      targetType: 'ngr_definition',
      targetId: String(newDef._id),
```
